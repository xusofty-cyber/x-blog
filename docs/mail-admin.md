# 后台邮箱管理（v1 + v2 分组列表）

在 `/admin/mail` 切换多个 QQ 邮箱查看邮件。第一版只读加标记已读，不发件、不删除、不移动邮件，不在博客库里存邮件正文与附件，打开时按需经 IMAP 拉取。

## v3.1：左侧栏不显示数字邮箱

- 数字邮箱就是 QQ 号本身，分组标题已是 QQ 号，左侧不再单列数字邮箱一行，省空间。
- 数字邮箱并未去掉：点分组标题即查看该组的数字邮箱（没有数字邮箱的组则查看该组第一个邮箱）；字母、Foxmail 邮箱仍在分组下方单列，点击切换。

## v3：分组总授权码 + 邮件删除 + 侧边栏不留白

- 一个 QQ 只有一个总授权码，数字、字母、Foxmail 三个邮箱共用：添加 QQ 时填一次总授权码，给该 QQ 加邮箱时不再填授权码，换码时在更新面板里填一次新总授权码，后端会用组下所有邮箱各测一次登录，任何一个失败都不保存。
- 邮件删除：列表每封邮件旁和正文顶部都有“删除”按钮，点后二次确认，后端经 IMAP 给邮件打 \Deleted 再按 UID 清除；删除后它将从收件箱消失，QQ 邮箱里一般可在已删除里找回，具体以 QQ 邮箱为准。
- 侧边栏留白修复：后台侧边栏改为固定视口高度（sticky top-0 h-screen），随页面滚动时仍停在左侧，不再随主内容拉长；邮箱列表不再设 45vh 上限，改为随侧边栏整体滚动，底部操作区始终在视口底部。
- 迁移 `20261102213000_group_authcode`：分组上加加密授权码列，把每组最早一个邮箱的加密授权码原样抄到分组上、收紧非空后，才删掉邮箱上的旧列；任何一步失败迁移整体回滚，不会先删后抄。部署前仍需备份，部署后核对分组数、邮箱数与分组授权码总长度与部署前一致。

## v2：侧边栏分组列表

- 切换不再用下拉框：后台左侧“邮箱管理”导航项下方就是按 QQ 分组的邮箱列表，点“邮箱管理”可以把列表收起来或展开。
- 一个 QQ 分组下最多 3 个邮箱（数字、字母、Foxmail 各一），列表项里直接展示这最多 3 个邮箱名，不用记某个邮箱属于哪个 QQ。
- 每个 QQ 分组旁有一个小的“更新”按钮，只有点了它才在邮箱页出现更新面板（改备注名、改邮箱、换授权码、给该 QQ 加邮箱、删邮箱/删 QQ）；平时切换时不显示更新表单。
- 更新授权码时留空表示保留原来的，不会清空；改了邮箱或授权码时会先测 IMAP 登录，通了才保存。

## 后端

- NestJS 模块：`apps/api/src/mail/`，路由前缀 `/api/mail`，全部接口用现有 `JwtAuthGuard`，只给后台管理员。
- 账号模型：`MailAccount`（Prisma 迁移 `20261102195000_add_mail_account`），只存备注名、邮箱、IMAP 主机/端口与加密后的授权码。
- 加密：AES-256-GCM，密钥只来自服务器 `.env` 的 `MAIL_ENCRYPTION_KEY`（32 字节 base64 或 hex），不进仓库、不进日志、不进聊天。添加与换授权码时先测 IMAP 登录，通了才保存。
- IMAP：`imap.qq.com:993` SSL，每次请求新建连接、用完即断开；列表按页拉取信封，详情再解析全文与附件；附件超过 30MB 时后端拒绝，提示去 QQ 邮箱下载。

## 前端

- 后台导航加“邮箱管理”，页面 `apps/web/app/admin/mail/page.tsx`：顶部下拉切换账号，左侧列表加搜索与分页，右侧正文用 `sandbox=""` 的 iframe 渲染 HTML（脚本被沙箱拦截），附件经带 Bearer 的 fetch 下载。

## 数据迁移安全（v2 必须遵守）

- 迁移 `20261102211000_add_qq_group` 是纯加法：新建 QqGroup 表、每个已有邮箱账号原地变成一个分组（分组 id 复用账号 id）、给 MailAccount 加分组与类型两列，**不删任何 MailAccount 行、不改 encryptedAuthCode**。
- 部署前不要重新生成 `MAIL_ENCRYPTION_KEY`：已有授权码是用服务器 .env 里那把密钥加密的，换了密钥就解不出来，等于全部授权码丢失。
- 部署前先给数据库做一次备份（例如 pg_dump 到服务器项目外或别处），迁移后再核对分组数与邮箱数与部署前一致。

## 服务器部署前置

部署前先确认服务器项目根 `.env` 里有 `MAIL_ENCRYPTION_KEY`，没有时在服务器上用 python3 生成并追加（不要把值发到聊天里，也不要写进仓库）：

```bash
python3 -c "import secrets,base64; print(base64.b64encode(secrets.token_bytes(32)).decode())"
# 把输出追加为 MAIL_ENCRYPTION_KEY=... 到 .env（权限保持 600）
```

其余部署流程与手册一致：推 main、服务器跑 `deploy/deploy.sh`、健康检查。本次改动单独做，不捆种子文章与凭证有效期那批未部署改动。

## 站长使用步骤

1. 每个 QQ 号先在 QQ 邮箱设置里开启 IMAP 服务并生成授权码（不是 QQ 密码）。
2. 登录博客后台 `/admin/mail`，填备注名、QQ 邮箱与授权码，添加并测试通过后即可切换查看。
3. 换 QQ 密码后授权码会失效，在同一页更新授权码即可。
